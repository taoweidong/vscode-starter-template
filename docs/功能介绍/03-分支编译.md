# 03 · 分支编译（构建控制台）

> 「分支编译」= Webview 弹框表单 + 侧边栏任务列表：填写分支名等信息提交构建任务，
> HTTP 接口创建任务，列表实时轮询展示状态与进度。**HTTP 接口默认打桩模拟**，
> 配置真实地址后零改动切换——这是「表单 → HTTP 接口 → 列表展示」的完整示例。
>
> 布局（v2.2.2）：页面占面板宽度 ~95%；宽面板下**双卡片并排**——左侧「提交构建」
> 表单卡、右侧「构建任务」列表卡（5 : 7），窄面板（≤1000px）自动上下堆叠。

## 如何使用

1. `Ctrl+Shift+P` → 「Extension Starter: 打开分支编译控制台」（或「构建任务」视图标题栏「打开控制台」按钮，或单击任一任务条目）；
2. 弹框表单：**分支名**（必填）+ **构建类型**（完整/增量）+ **备注**（选填）→ 「提交构建」；
3. 「构建任务」列表实时轮询（3s）：排队中 → 构建中（进度条）→ 成功 / 失败；
4. 侧边栏「构建任务」视图同步展示任务列表（状态图标 / 进度 / 类型），标题栏可刷新；
5. 手动刷新：列表卡头「刷新」按钮。

## 打桩演示规则（默认模式）

- 提交后约 250ms 受理 → 排队 1.5s → 构建中（进度按 600ms 步进 14%）→ 成功；
- **分支名包含 `fail`（不区分大小写）→ 构建失败**——用于演示失败路径，无随机数；
- 历史任务保存在内存（扩展窗口生命周期内），上限 50 条。

## 对接真实 HTTP 接口

设置 `extStarter.buildApiBaseUrl`（如 `http://127.0.0.1:3000`，**修改后需重载窗口生效**——
接口客户端在激活时按配置创建一次）后：
`POST /builds` 提交任务、`GET /builds` 拉取列表；服务端契约见
`src/extension/features/build/buildApiClient.ts` 的 `BuildSubmitPayload` / `BuildTask`。
页面与协议层零改动；字段或路径不一致时只需改 `HttpBuildApiClient`。

## 常见问题

- **提交后一直转圈？** 打桩模式单任务全程约 7s；真实模式取决于服务端；
  提交有 10s 超时保护，超时后自动解锁（结果以任务自身落定为准）；
- **「分支名不能为空」**：必填校验，错误会直接定位到分支名控件；
- **任务列表是空的**：打桩任务保存在扩展窗口内存中，重载窗口即清空。
