# 03 · 插件开发指南

> 目标：把这个「示例插件」变成「你的插件」。每一步都给出改哪里、怎么验证。
> 全程遵循 `agent.md` 约定：**每次改动收尾前执行 `npm run gate`**。

## 0. 先理解模板架构

```text
src/models（数据模型）
   ↓
src/domain（领域 Schema：字段定义单一来源，驱动校验与表单）
   ↓
src/services（业务：校验/清洗/事件）← ItemService
   ↓
src/services/stores（IItemStore 数据源抽象：JSON 文件 / 全局存储 / 可替换）
   ↑ 读写
src/providers（树视图 + Webview 表单面板）    src/webview（Vue 3 页面：host 控制器 + SchemaForm + 设计系统）
   ↑ 调用
src/commands（命令注册中心）← src/extension.ts（组装一切）
src/tasks（启动任务框架）  src/features（四个功能页面）
```

数据流是单向的：**界面 → ItemService → IItemStore**，任何变更通过 `onDidChangeItems`
事件自动刷新视图。你二创时大部分工作只发生在 `src/domain/itemSchema.ts`（加字段）。

## 1. 改成你的插件身份（package.json）

| 字段          | 说明                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------- |
| `name`        | 插件英文标识（npm 规则：小写+连字符）                                                    |
| `displayName` | 市场显示名（建议与界面品牌一致）                                                         |
| `publisher`   | 你的发布者 ID（vsce 创建：`npx vsce login <id>`）                                        |
| `repository`  | 已指向本仓库，改成你的 fork 地址（`homepage` / `bugs` 一并改）                           |
| `icon`        | 已内置 `media/icon.png`（128×128）；换图标改 SVG 后跑 `npx tsx scripts/generate-icon.ts` |

界面品牌（侧边栏「CRUD Starter」、命令分类）在 `package.json` 的
`contributes.viewsContainers` / `commands[].category` 与 `src/constants.ts` 中，一并替换。

## 2. 改数据模型与表单（最常见的改动，只改一处）

以给条目加一个「负责人 owner」字段为例：

1. **领域 Schema** `src/domain/itemSchema.ts` 的 `ITEM_FIELD_DEFS` 加一行：

   ```ts
   { key: 'owner', type: 'text', label: '负责人', placeholder: '选填' },
   ```

2. **完成**。表单（`FORM_SCHEMA` 由领域定义自动派生）、取值、回填、校验、克隆全部
   自动生效——页面与组件里没有任何业务字段特例。
   想要更强的类型提示，可选地在 `src/models/item.ts` 的 `Item` / `ItemDraft` 补
   `owner: string`（不补也不影响功能：未声明的 string / number / boolean 字段会透传保留）。

字段类型可用：`text` / `textarea` / `select`（配 `options`）/ `tags` / `boolean`。
要新控件类型：在 `src/webview/components/fields/` 加一个字段组件并在 `SchemaForm` 注册分发。

> 迁移旧数据：`JsonFileStore.load()` 返回前补默认值即可。

## 3. 更换数据源（接 API / 数据库）

实现 `src/services/stores/itemStore.ts` 的接口即可：

```ts
export class ApiStore implements IItemStore {
  constructor(private readonly baseUrl: string) {}
  async load(): Promise<Item[]> {
    const res = await fetch(`${this.baseUrl}/items`)
    return res.json() as Promise<Item[]>
  }
  async save(items: Item[]): Promise<void> {
    await fetch(`${this.baseUrl}/items`, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(items),
    })
  }
}
```

然后在 `src/extension.ts` 的 `createStore()` 返回 `new ApiStore(...)`。
业务层、树视图、表单、四个功能页面**零改动**。数据量大时把 ItemService 的
「读-改-全量写」改成按 id 增删改。

## 4. 新增命令 / 视图（三处同步，缺一不可）

门禁的静态一致性检查（第 ⑥ 步）会校验三处的一致性：

1. `src/constants.ts`：`COMMAND` / `VIEW` 加 ID；
2. `package.json`：`contributes.commands` 声明；要出现在菜单就配 `menus`
   （`view/title` / `view/item/context` / `editor/context` / `explorer/context`，注意写 `when`）；
3. `src/commands/index.ts`：`register(COMMAND.xxx, callback)` 写实现。

> 记住右键菜单传参约定：`view/item/context` 收到 `(树节点元素, 多选集合)`，
> 树节点要用 `toItem()` 归一化成 `Item`。

## 5. 扩展启动任务（动作类脚本）

实现 `StartupTask` 接口（`id / title / run()`）并在 `src/tasks/taskRegistry.ts`
的 `TASKS` 数组注册——调度、异常降级、输出通道、「环境信息」视图展示全部自动生效。
内置 `environmentTask`（环境检测）是完整参考实现。

## 6. 质量门禁与测试

- **每次收尾**：`npm run gate`（协议见 `agent.md`；门禁含 lint / 格式 / 类型 / 构建 /
  静态一致性 / 单测覆盖率 / 宿主集成共 8 步，fail-fast）；
- **加业务逻辑时**：优先写单元 / 组件测试（`src/test/unit/**/*.spec.ts`，Vitest 不启动
  VSCode，服务层用内存 Store 即可）；宿主集成用例在 `src/test/extension.test.ts` 补
  `suite` 可当模板。测试分层与工具见 `agent.md` 与 `docs/需求与优化方案/01`（NFR-07）；
- **测 UI 逻辑**：树视图分组 / 过滤、表单组件渲染都有现成用例可仿写；
  Webview 页面还有 Playwright 端到端用例（`tests/e2e/`，`npm run test:e2e`）。

## 7. 打包发布

```bash
npm run gate            # 门禁全绿后再打包
npm run package:vsix    # 一键：类型检查 + 生产构建 + vsce package，产出 .vsix
npx vsce publish        # 发布到市场（需 publisher 账号 + PAT）
```

- vsce（`@vscode/vsce`）已内置在 devDependencies，打包 / 发布都**无需全局安装**；
- 产物为仓库根目录的 `<name>-<version>.vsix`（已被 `.gitignore` 排除）；
- 离线验证：扩展面板 `…` → `从 VSIX 安装…` → 选择生成的 .vsix，逐个打开功能页面确认。

核对清单：`publisher` 已改 ✓ / 128×128 图标 ✓ / `repository` 指向你的仓库 ✓ /
`npm run gate` 全绿 ✓。

## 8. 推荐的文件阅读顺序

1. `agent.md`（约定）→ 2. `src/extension.ts`（组装全貌）→ 3. `src/domain/itemSchema.ts`
   （领域 Schema：数据与表单的单一来源）→ 4. `src/services/itemService.ts`（业务核心）→ 5. `src/providers/itemsTreeDataProvider.ts`（视图如何消费数据）→ 6. `src/webview/`
   （Vue 3 页面框架：`host/` 控制器 → `components/SchemaForm` → 任一 `apps/` 页面）→ 7. 挑一个 `src/features/` 目录读完整链路。
