### 2.3 图标问题：全链路诊断与病根（**当前图标全不显示**）

**症状**：webview 页面内所有 codicon 图标不可见（按钮图标、空态图标、表单错误图标等），宿主侧树视图图标正常。

**逐层排除记录**：

| 检查项                               | 结论                                                             |
| ------------------------------------ | ---------------------------------------------------------------- |
| `iconNames.ts` 语义名 → codicon 类名 | ✅ 正确（24 个语义名，映射到真实 codicon）                       |
| 各 `apps/*/main.ts` 是否引字体 CSS   | ✅ 5 个入口**全部** `import '@vscode/codicons/dist/codicon.css'` |
| `codicon.css` 是否含 `@font-face`    | ✅ 存在，`src: url("./codicon.ttf?...") format("truetype")`      |
| `tokens.css` 是否含字体定义          | ⚠️ 不含（字体来自 codicons 包，符合预期）                        |
| CSS 构建后 `url()` 是否被改写        | ❌ **被改写成站点根绝对路径 → 病根**                             |
| 宿主 `localResourceRoots`            | `dist/webview`（`assetResolver.ts:26-28`）                       |
| 宿主 CSP `font-src`                  | ✅ 已授权 `cspSource`，不是 CSP 问题                             |

**病根（构建产物直接实证）**：

```
修复前：@font-face{font-family:codicon;font-display:block;
        src:url(/assets/codicon-CMYWzYni.ttf?9aab6318a6710999273bab9c78a9fd71) format("truetype")}

修复后：@font-face{font-family:codicon;font-display:block;
        src:url(./codicon-CMYWzYni.ttf?9aab6318a6710999273bab9c78a9fd71) format("truetype")}

站点根绝对引用残留：无残留 ✅   manifest 入口数：20（不变）✅
```

**传导链**：`vite.config.ts` 未设 `base` ⇒ 默认 `'/'` ⇒ Vite 把 CSS 中的相对 `url()` 改写为 `/assets/xxx`（站点根绝对路径）⇒ webview 中该 URL 解析到 webview 域根而非 `dist/webview/` ⇒ **超出 `localResourceRoots` ⇒ 404** ⇒ 字体加载失败 ⇒ 所有 `.codicon-*` 渲染为空白。

> **为什么 e2e 没发现**：`tests/e2e/server.mjs` 的 `ROOT` 指向 `dist/webview/`，静态路由把 `/assets/xxx` 解析为 `ROOT/assets/xxx`——**恰好与站点根绝对路径对齐**，形成假绿。且 e2e 从未断言过字体加载。

**宿主侧树视图图标不受影响**（用 workbench 自带 codicon），`ThemeIcon` 名称、`$(xxx)` 命令图标、`media/icon.svg|png` 全部有效——本次问题**仅限 webview 内部**。

## 4. 专项一：图标修复（**最高优先级，1 行 + 3 处配套**）

│   ├── constants.ts           ← 由 src/constants.ts 迁入

**边界规则（写进 README）**：

- `src/extension/**` —— 只 import `vscode`，**不 import Vue / Webview 侧代码**；

**现状**：`tsconfig.json` + `tsconfig.webview.json` 两份，宿主侧配置里混了 Node 侧类型。

## 6. 四类示例的具体优化设计

### 6.1 ① 环境检测 —— 可插拔探针接口（需求 1）

**现状问题**：`environmentTask.ts`（175 行）把 Python / Node / npm / Git / 操作系统 / VSCode 六项**硬编码**在一个 `run()` 里。加一种语言要改函数体；用户要求「预留其他类型检查接口」。

**改造方案**：拆成「探针注册表 + 通用执行器」。

```ts
// src/extension/tasks/probes.ts —— 新增（示例接口）
export interface EnvironmentProbe {
  /** 探针 id（稳定标识） */
  id: string
  /** 展示名 */
  label: string
  /** 候选命令（按序回退，第一个有输出的胜出） */
  commands: readonly string[]
  /** 从输出中提取版本号；缺省取首行 */
  parse?: (raw: string) => string
  /** 缺失时的提示文案 */
  missingHint?: string
}

/** 探针注册表：新增语言/工具 = 往数组加一项，零改动其他文件 */
export const ENVIRONMENT_PROBES: readonly EnvironmentProbe[] = [
  {
    id: 'python',
    label: 'Python',
    commands: ['py -3 --version', 'python --version', 'python3 --version'],
    parse: (raw) => raw.replace(/^Python\s*/i, ''),
  },
  { id: 'node', label: 'Node.js', commands: ['node --version'] },
  { id: 'npm', label: 'npm', commands: ['npm --version'] },
  {
    id: 'java',
    label: 'Java',
    // java -version 输出到 stderr，javac -version 输出到 stdout，双通道兜底
    commands: ['java -version', 'javac -version'],
    parse: (raw) => raw.replace(/^javac\s*/i, '').replace(/^java\s*/i, ''),
  },
  {
    id: 'git',
    label: 'Git',
    commands: ['git --version'],
    parse: (raw) => raw.replace(/^git\s*/i, ''),
  },
]
```

**「点击后检测」的实现**（当前是激活时自动跑 + 手动刷新按钮）：

| 改动点   | 现状                                     | 目标                                                          |
| -------- | ---------------------------------------- | ------------------------------------------------------------- |
| 触发时机 | `runStartupTasks` 默认 `true`，激活即跑  | **默认不自动跑**，改为**点击「检测环境」按钮 / 树节点**才跑   |
| 配置项   | `crudStarter.runStartupTasks`（boolean） | **保留但默认改 `false`**，语义不变                            |
| 树视图   | 一次跑完 6 项平铺                        | 保留分组结构，**每个探针节点可单独点击重检**                  |
| 新增     | —                                        | 树节点 `command` 绑定「重新检测此项」，单探针失败不阻塞其他项 |

**Java 探测注意**：`java -version` 输出到 **stderr**（不是 stdout），且可能带 `openjdk version "17.0.9" 2023-10-17` 前缀。
现有 `execCapture`（`environmentTask.ts:36-49`）已兼容「err 为空时取 stderr 首行」，但 `java -version` 在部分 JDK 上退出码为 0 ⇒ 走 stderr 分支 ⇒ 需 `parse` 提取引号内版本号。

**文件变更**：

| 文件                                                 | 动作                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------- |
| `src/extension/tasks/probes.ts`                      | **新增**：探针接口 + 注册表（Python/Node/npm/Java/Git）     |
| `src/extension/tasks/environmentTask.ts`             | **改造**：从硬编码改为遍历 `ENVIRONMENT_PROBES`（净减行数） |

> **保留 `taskRunner` / `StartupTask` 抽象**：它是「长任务 + 超时 + 取消 + 降级」的通用件，

### 6.2 ② 串口命令控制台 —— 保留并优化（需求 2）
