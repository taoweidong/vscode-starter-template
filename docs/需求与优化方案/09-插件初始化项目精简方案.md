## 4. 四类示例的具体设计

### 4.1 ① 环境检测 —— 可插拔探针接口（需求 1）

**现状问题**：`environmentTask.ts` 把 Python / Node / npm / Git / 操作系统 / VSCode 六项**硬编码**在一个 175 行的 `run()` 里。
加一种语言要改函数体；用户要求「预留其他类型检查接口」。

**改造方案**：拆成「探针注册表 + 通用执行器」。

```ts
// src/features/environment/probes.ts —— 新增（示例接口）
export interface EnvironmentProbe {
  /** 探针 id（树节点 contextValue / 稳定标识） */
  id: string
  /** 展示名 */
  label: string
  /** 候选命令（按序回退，第一个有输出的胜出） */
  commands: readonly string[]
  /** 从输出中提取版本号；缺省取首行 */
  parse?: (raw: string) => string
  /** 缺失时的提示文案 */
  missingHint?: string
}

/** 探针注册表：新增语言/工具 = 往数组加一项，零改动其他文件 */
export const ENVIRONMENT_PROBES: readonly EnvironmentProbe[] = [
  {
    id: 'python',
    label: 'Python',
    commands: ['py -3 --version', 'python --version', 'python3 --version'],
    parse: (raw) => raw.replace(/^Python\s*/i, ''),
  },
  { id: 'node', label: 'Node.js', commands: ['node --version'] },
  { id: 'npm', label: 'npm', commands: ['npm --version'] },
  {
    id: 'java',
    label: 'Java',
    commands: ['java -version', 'javac -version'],
    parse: (raw) => raw.replace(/^javac\s*/i, ''),
  },
  {
    id: 'git',
    label: 'Git',
    commands: ['git --version'],
    parse: (raw) => raw.replace(/^git\s*/i, ''),
  },
]
```

**「点击后检测」的实现**（当前是激活时自动跑 + 手动刷新按钮）：

| 改动点   | 现状                                        | 目标                                                                |
| -------- | ------------------------------------------- | ------------------------------------------------------------------- |
| 触发时机 | `runStartupTasks` 配置默认 `true`，激活即跑 | **默认不自动跑**，改为**点击「检测环境」按钮 / 树节点**才跑         |
| 配置项   | `crudStarter.runStartupTasks`（boolean）    | **保留但默认改 `false`**，语义不变                                  |
| 树视图   | 一次跑完 6 项平铺                           | 保留分组结构（探针分组 → 版本条目），**每个探针节点可单独点击重检** |
| 新增     | —                                           | 树节点 `command` 绑定「重新检测此项」，单探针失败不阻塞其他项       |

**Java 探测注意**：`java -version` 输出到 **stderr**（不是 stdout），且可能带 `openjdk version "17.0.9" 2023-10-17` 前缀。
现有 `execCapture` 已兼容「err 为空时取 stderr 首行」，但需确认 `java -version` 在部分 JDK 上退出码为 0 → 走 stderr 分支 → 需要 `parse` 提取引号内版本号。

**文件变更**：

| 文件                                       | 动作                                                        |
| ------------------------------------------ | ----------------------------------------------------------- |
| `src/features/environment/probes.ts`       | **新增**：探针接口 + 注册表（Python/Node/npm/Java/Git）     |
| `src/tasks/environmentTask.ts`             | **改造**：从硬编码改为遍历 `ENVIRONMENT_PROBES`（净减行数） |
| `src/providers/environmentTreeProvider.ts` | **改造**：探针节点可点击重检 + 单项失败隔离                 |
| `src/tasks/taskRegistry.ts`                | 不变（`TASKS` 数组仍是注册表）                              |

> **保留 `taskRunner` / `StartupTask` 抽象**：它是「长任务 + 超时 + 取消 + 降级」的通用件，
> 分支编译的 `BuildService` 也依赖 `tasks/types.ts` 的 `TaskSignal`。不因环境检测简化而废掉这层。

### 5.3 ⚠️ 门禁脚本的隐藏依赖（**最容易踩的坑**）

`scripts/checks/manifest.ts` 有**两处硬编码前缀**，改名后不改会直接让门禁第 ⑥ 步变红：

```ts
// :155  命令 ID 提取正则——只认 crudStarter 前缀
const commandPairs = [...commandBlock.matchAll(/(\w+):\s*'(crudStarter\.[a-zA-Z0-9-]+)'/g)]

// :198  特性开关配置前缀
const featuresPrefix = 'crudStarter.features.'
```

**修法**：把前缀从 `src/constants.ts` 的 `CONFIG.section` 动态读取，**彻底消除硬编码**：

```ts
const { CONFIG } = requireFromRoot('./out/constants.js')
const commandPairs = [
  ...commandBlock.matchAll(new RegExp(`(\\w+):\\s*'(${CONFIG.section}\\.[a-zA-Z0-9-]+)'`, 'g')),
]
const featuresPrefix = `${CONFIG.section}.features.`
```

这样以后再改名只需改 `constants.ts` 一处 —— **这才是「初始化模板」该有的门禁形态**。

### 5.4 兼容性

- **数据文件改名不兼容**：旧 `.vscode/crud-starter-items.json` 不再被读取。模板项目无历史包袱，可接受；README 注明迁移路径。
- **配置键改名不兼容**：用户旧设置 `crudStarter.storagePath` 失效。发布时在 CHANGELOG 注明。
- **Memento 键改名**：globalState 数据丢失（仅影响未开工作区场景）。
