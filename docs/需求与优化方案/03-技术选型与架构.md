## 1. 决策记录（ADR 汇总）

| ADR    | 决策                                                                                            | 备选（已放弃）                          | 理由                                                                                                                                     |
| ------ | ----------------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-01 | 语言全量 TypeScript：源码 / 构建脚本 / 门禁脚本 / 测试；`.vue` 用 `<script setup lang="ts">`    | JS/TS 混用                              | 单一语言、类型安全到边界（协议 / Schema / 脚本）；现宿主已 strict TS，剩余 JS 仅 `esbuild.js`（31 行）与 `gate.js`（195 行），迁移成本低 |
| ADR-02 | Webview 页面全部 Vue 3 SFC + Composition API                                                    | 原生字符串模板（现状）/ React / Svelte  | 3+ 页面需要组件复用、状态与测试；Vue 学习曲线平缓、SFC 与 Schema 驱动表单契合；React 更重、Svelte 生态较薄                               |
| ADR-03 | 双构建：Vite 构建 Webview + esbuild 构建扩展宿主                                                | 单一 Vite / webpack / esbuild Vue 插件  | Vite 对 SFC / HMR 生态最成熟；宿主 bundle 轻量诉求保持 esbuild；两者职责清晰互不干扰                                                     |
| ADR-04 | Vue runtime-only + 构建期预编译模板                                                             | runtime compiler                        | 严格 CSP 禁 `unsafe-eval`；预编译消除运行时编译器                                                                                        |
| ADR-05 | Vite 多入口 + `build.manifest`，宿主按 manifest 解析资源                                        | 单 bundle + data-page 路由 / 固定文件名 | 3+ 页面下按需加载、入口清晰；hash 文件名天然支持；固定名在共享 chunk 场景脆弱                                                            |
| ADR-06 | 状态：Composition API + `provide/inject` + `vscode.getState/setState`；不引入 Pinia             | Pinia                                   | 每个 Webview 是独立 JS 上下文，跨面板无共享状态；两三个页面无需全局 store                                                                |
| ADR-07 | 样式：自研语义令牌 + 轻量组件库；**禁止** Element Plus / Vuetify / Ant Design / Tailwind        | 通用 UI 框架                            | VSCode 插件必须融入宿主视觉；通用框架自带设计语言、体积大、主题适配差                                                                    |
| ADR-08 | VSCode Elements（Web Components）**仅作复杂控件备选**，不作基础依赖                             | 直接全量采用                            | 基础控件自研可控且零额外依赖；仅当下拉 / 表格等复杂控件视觉验收不达标时做专项 spike                                                      |
| ADR-09 | 领域校验：共享领域 Schema + 手写类型守卫                                                        | zod / yup                               | 扩展宿主保持零运行时依赖；Schema 同时驱动表单与服务端，手写守卫足够且可测                                                                |
| ADR-10 | 测试：Vitest（单元 + 组件，jsdom，`vscode` 模块 stub）+ Mocha/@vscode/test-electron（宿主集成） | 全部 Mocha / 全部 test-electron         | 单元层不下载 VSCode、秒级反馈（NFR-07）；集成层保留真实宿主验证                                                                          |
| ADR-11 | 脚本执行：`tsx` 运行 `scripts/*.ts`                                                             | ts-node / 预编译后 node                 | 零配置直跑 TS；devDependency 一枚                                                                                                        |
| ADR-12 | 打包：`@vscode/vsce` 进 devDependencies + `package:vsix` 脚本                                   | 依赖全局安装 vsce                       | FR-17 一键离线 .vsix；CI / 干净环境可复现                                                                                                |
| ADR-13 | 图标：`@vscode/codicons`（字体资源随 dist 分发）                                                | 内联 SVG / 图标字面量                   | 与宿主同一图标语言；字体方案体积小、使用一致；CSP 允许 `font-src ${cspSource}`                                                           |

## 2. 目标架构

```text
┌─────────────────────────── 扩展宿主（Node，esbuild → dist/extension.js）───────────────────────────┐
│  extension.ts（组装）                                                                              │
│   ├─ services/（ItemService：校验/队列/事件） ── stores/（IItemStore：JSON 文件 / Memento / 可替换） │
│   ├─ providers/（原生 TreeView × 6，保持 VSCode API，不迁移 Vue）                                  │
│   ├─ features/（init / featureConfig / staticConfig / build）                                      │
│   ├─ tasks/（TaskRunner：超时 / 取消 / 逐任务事件）                                                 │
│   └─ webview/host/                                                                                │
│        ├─ pages.ts        页面注册表（id / entry / title / panelOptions）                           │
│        ├─ webviewController.ts  通用面板生命周期（create/reveal/dispose/消息分发/dirty/serializer）  │
│        ├─ webviewHtml.ts  HTML 外壳（CSP + manifest 资源解析 + nonce）                              │
│        └─ assetResolver.ts 读取 dist/webview/.vite/manifest.json → asWebviewUri                     │
└──────────────────────────────────┬─────────────────────────────────────────────────────────────────┘
                                   │ postMessage（protocol.ts：判别联合 + 运行时守卫，双向）
┌──────────────────────────────────▼─────────────────────────────────────────────────────────────────┐
│  Webview（浏览器环境，Vite → dist/webview/<page>.js|css，Vue 3 runtime-only）                        │
│   ├─ apps/<page>/App.vue      页面根组件（itemForm / featureConfig / importWizard / gallery…）       │
│   ├─ components/SchemaForm.vue + fields/*.vue（字段组件注册表）                                     │
│   ├─ ui/（Button/Input/Select/Checkbox/FormField/EmptyState/Loading/Badge/Toolbar…，只消费语义令牌）│
│   └─ shared/（useVsCodeApi / 校验 / 状态持久化）                                                    │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

数据流原则（不变）：**界面 → ItemService（权威校验）→ IItemStore**；Webview 只做即时提示，宿主校验结果带 `field` 键回传定位。

## 4. 构建管线

### 4.1 Vite（Webview）

```ts
// vite.config.ts（关键配置示意）
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'
import { WEBVIEW_PAGES } from './src/webview/pages' // 注册表单一来源

export default defineConfig({
  plugins: [vue()],
  resolve: { alias: { vue: 'vue/dist/vue.runtime.esm-bundler.js' } }, // ADR-04
  define: {
    __VUE_OPTIONS_API__: 'true',
    __VUE_PROD_DEVTOOLS__: 'false',
    __VUE_PROD_HYDRATION_MISMATCH_DETAILS__: 'false',
  },
  build: {
    outDir: 'dist/webview',
    emptyOutDir: true,
    manifest: true, // ADR-05：宿主按 manifest 解析 hash 文件名
    sourcemap: 'hidden', // 不进 vsix
    assetsInlineLimit: 0, // 禁 data-URI，资源全部走 asWebviewUri（CSP 友好）
    cssCodeSplit: true,
    rollupOptions: {
      input: Object.fromEntries(WEBVIEW_PAGES.map((p) => [p.id, p.entry])),
    },
  },
})
```

说明：Vite 版本锁定与项目 Node 引擎兼容的 LTS（如 Vite 6 支持 Node 18+；若用 Vite 7 需将开发环境 Node 提升至 ≥ 20.19——在 M2-T2.3 一并定版并写入 `engines` 与文档）。

## 5. Webview 宿主框架

### 5.1 页面注册表（`src/webview/pages.ts`）

```ts
export interface WebviewPageDef {
  id: 'itemForm' | 'featureConfig' | 'importWizard' | 'gallery'
  title: string
  /** Vite 入口（相对仓库根），构建与宿主共用 */
  entry: string
  /** 面板选项（retainContextWhenHidden 一律 false，见 ADR/04） */
  panelOptions?: { enableCommandUris?: false }
}
export const WEBVIEW_PAGES: readonly WebviewPageDef[] = [
  { id: 'itemForm', title: '条目表单', entry: 'src/webview/apps/itemForm/main.ts' },
  { id: 'featureConfig', title: '特性配置', entry: 'src/webview/apps/featureConfig/main.ts' },
  { id: 'importWizard', title: '批量导入', entry: 'src/webview/apps/importWizard/main.ts' },
  { id: 'gallery', title: '组件画廊（开发）', entry: 'src/webview/apps/gallery/main.ts' },
]
```

门禁校验：注册表 ↔ `dist/webview/.vite/manifest.json` 入口一致；「新增页面 = 注册表一项 + 页面目录」即 FR-16-AC2。

### 5.2 通用面板控制器（`webviewController.ts` 职责清单）

- `createOrShow(pageId, context) / reveal / dispose`（幂等 dispose，消除现状的重入问题，P1-17）；
- 消息分发：按 `protocol.ts` 守卫过滤，未知消息记日志不抛错；
- 请求幂等：`submit` 在途时忽略重复提交；
- dirty 跟踪：页面上报 `dirty` 状态，切换目标 / 关闭前宿主弹确认；
- 状态持久化：`webview.setState/getState` + `registerWebviewPanelSerializer`（窗口重载恢复）；
- 错误兜底：`init` 失败 / 资源缺失时输出诊断信息到面板与输出通道。

### 5.4 CSP 矩阵（目标态）

```text
default-src 'none';
script-src 'nonce-{nonce}' {cspSource};
style-src {cspSource};
img-src {cspSource} data:;
font-src {cspSource};
connect-src 'none';
base-uri 'none'; form-action 'none'; frame-ancestors 'none';
```

- `nonce` 授权入口脚本，`cspSource` 允许 Vite 产物的静态 import chunk 与外部 CSS / codicon 字体；
- 禁止出现：`unsafe-eval`、`unsafe-inline`、`v-html`、内联事件；
- **内联样式策略（07 §2 实验取证后修订，原表述「内联 `style` 属性（布局白名单除外）」有误导——
  CSP 没有白名单机制）**：
  - 禁**模板静态 `style="..."` 属性**：`style-src` 无 `'unsafe-inline'`，会静默拦截（`style` 属性读回为空串）；
  - `:style` / `v-bind:style` **绑定不受影响**：Vue 编译为 CSSOM（`el.style.setProperty`），
    不经过 HTML 属性解析，实测三条路径（直接赋值 / `cssText` / `setProperty`）均放行；
  - 门禁已按此实现（第 6 条：只拦静态 `style=` 属性，不误伤 `:style`）。
- 门禁对 `dist/webview/**` 做静态扫描：无 `eval(` / `new Function(` / `unsafe-eval` / `unsafe-inline` 字样。

### 5.5 消息协议（`protocol.ts`）

```ts
// 宿主 → Webview
export type HostMessage =
  | {
      type: 'init'
      page: string
      schema: FieldDef[]
      value: unknown
      extra?: Record<string, unknown>
    }
  | { type: 'submitAck'; ok: true }
  | { type: 'error'; message: string; field?: string } // field 定位控件
// Webview → 宿主
export type WebviewMessage =
  | { type: 'ready' }
  | { type: 'dirty'; dirty: boolean }
  | { type: 'submit'; draft: Record<string, unknown> }
  | { type: 'cancel' }

export function isWebviewMessage(v: unknown): v is WebviewMessage {
  /* 逐字段窄化 */
}
export function isHostMessage(v: unknown): v is HostMessage {
  /* … */
}
```

守卫与类型同文件，宿主 / Webview 共享；两侧 `onDidReceiveMessage` / `addEventListener('message')` 一律先过守卫（修复 W7）。

## 7. 一键打包离线 .vsix（FR-17 设计）

### 7.1 工具链内置

- `@vscode/vsce` 加入 devDependencies（ADR-12），本地 / CI 无需全局安装；
- `npm run package:vsix` = `npm run package`（类型检查 + 双构建）+ `vsce package --no-dependencies`；
- 产物命名：`{name}-{version}.vsix`，输出到仓库根（已在 `.gitignore`：`*.vsix`）。

### 7.2 打包内容控制（`.vscodeignore` 目标态）

```text
包含：dist/extension.js、dist/webview/**（不含 *.map）、media/**、README.md、CHANGELOG.md、LICENSE
排除：scripts/**、agent.md、src/**、out/**、docs/**、.github/**、*.ts、tsconfig*、vite/vitest/eslint 配置、package-lock.json
```

### 7.3 门禁与 BuildService 复用

- 门禁新增步骤：`vsce ls` 输出与白名单比对（超出即失败）+ 发布元数据检查（publisher 非占位、icon 存在、LICENSE 存在）—— publisher 未配置时允许 `--allow-missing-repository` 类降级但必须显式警告；
- `BuildService` 的 vsce 段改为调用同一 devDependency（`npx --no-install vsce` 将天然可用），并把「未安装 vsce」「打包失败」「元数据缺失」三类错误分开（修复 02-P2 / FR-14-AC5）。

### 7.4 离线安装验证（人工 / 集成各一条）

- 集成：测试内断言 `dist/webview/manifest.json` 与外壳引用一致；
- 人工：扩展面板 `…` → `从 VSIX 安装…` → 打开三个页面验证（操作指导 03 第 7 节改写为 `npm run package:vsix`）。

## 8. 迁移顺序与回滚

1. **先底座后页面**：M2 建立 Vite/Vue/单测管线（此时旧渲染器仍在用）→ M3 设计系统 → M4 逐页迁移，旧 `formHtml.ts` 在最后一页迁完后删除（双渲染器短期共存，feature flag 不需要——页面入口逐个切换）；
2. **每页迁移即带组件测试与画廊登记**，不留「后补测试」；
3. **回滚**：任一页面迁移失败可单独还原该页入口（宿主 `pages.ts` 指回旧渲染器），构建管线互不影响；
4. **宿主行为零变更窗口**：M2/M3 期间不改任何业务逻辑，M1（数据可靠性）独立并行，冲突面最小。

## 9. 风险与缓解

| 风险                                                | 缓解                                                                                                          |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| CSP 与 Vite 产物冲突（chunk / 字体 / data-URI）     | `assetsInlineLimit: 0`、`cspSource` 授权 chunk、门禁静态扫描；M2-T2.3 以「空壳页面在真实 Webview 打开」为验收 |
| `acquireVsCodeApi` 只能调用一次                     | `shared/useVsCodeApi.ts` 模块级单例 + 单测覆盖                                                                |
| Vite 版本与 Node 18 引擎不匹配                      | M2 定版（Vite 6 或提升开发环境 Node ≥ 20）并写入 `engines` 与文档                                             |
| vue-tsc / SFC 类型检查拖慢门禁                      | 与 tsc 并行执行；`check-types` 拆分可单独跑 webview                                                           |
| 组件视觉不达 VSCode 原生                            | 04 文档令牌表 + 画廊验收 + VSCode Elements 备选 spike（ADR-08）                                               |
| vsce 对 manifest 校验严格（icon/LICENSE/publisher） | `package:vsix` 前置元数据检查并给出中文修复指引；占位 publisher 在模板期允许但必须显式提示                    |
| 双构建产物互相覆盖                                  | `dist/extension.js`（esbuild）与 `dist/webview/`（Vite `emptyOutDir` 仅清自身）目录隔离                       |
