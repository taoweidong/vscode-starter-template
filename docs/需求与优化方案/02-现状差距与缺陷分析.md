## 1. 结论摘要

- **P0 缺陷 5 项**：集中在数据持久化与信任边界，其中 3 项可造成**用户数据丢失**，1 项使模板最核心的「加字段」承诺失实，1 项在不受信任仓库中构成任意代码执行。
- **P1 缺陷 17 项**：并发与生命周期、批量与最新态、任务/构建互斥、测试与门禁工程化。
- **P2 缺陷 30+ 项**：Webview 细节、命令边界、UI 规范漂移、文档漂移、打包细节。
- **根因 6 条**（§9）：持久化契约过窄、Schema 只到渲染层、生命周期静态绑定、命令基于旧快照、任务无生命周期契约、门禁与测试面向「演示仓库」而非「可改名模板」。
- **新增需求差距**：当前**没有**不依赖 VSCode 宿主的单元测试层（NFR-07 ❌）；当前**无法**一条命令产出 .vsix（FR-17 ❌）。

## 2. 架构现状评估

**优点（保留并强化）**：

1. 分层清晰：models → services → stores（`IItemStore` 可替换）→ providers / commands，`extension.ts` 只做组装；
2. 注册表模式：命令（constants 单一来源）、启动任务（`taskRegistry`）、初始化步骤三处一致；
3. Schema 驱动的表单思想正确（渲染 / 取值 / 回填由 `FORM_SCHEMA` 驱动）；
4. 门禁意识领先同类模板（类型检查 + 构建 + 静态一致性 + 测试一体）；
5. 文档完备（README + 操作指导 3 篇 + agent.md 协议 + CHANGELOG）。

**结构性瓶颈**：

1. 持久化只有「全量 load/save」契约，无版本、无原子性、无冲突检测；
2. Schema 只驱动渲染层，领域校验 / 草稿映射 / 克隆在 4 处白名单复制；
3. store / watcher 在激活时一次性绑定，配置与工作区变化后静默错位；
4. 变更事件粗粒度（`EventEmitter<void>`），命令基于树节点旧快照写回；
5. Webview 为 380 行字符串模板 + 内联 JS，无组件模型、无类型、无组件测试，无法支撑 3+ 页面扩展。

## 3. P0 缺陷（数据丢失 / 安全 / 核心承诺失实）

### P0-01 损坏处理自动移走文件并返回空数组，备份失败静默 —— ✅ 已修复（M1，见 CHANGELOG [Unreleased]）

- **位置**：`src/services/stores/jsonFileStore.ts:14-30`（load 的 catch 分支）、`:39-51`（`backupCorruptedFile`）。
- **问题**：除 `FileNotFound` 外一切异常（BOM、JSONC、非数组 JSON、权限错误、文件占用）都走「损坏」流程：`fs.promises.rename` 移走原文件 → 返回 `[]`；外层 `catch {}` 静默吞掉备份失败，注释明示「后续保存会覆盖」。
- **影响链**：合法但非数组的 JSON（如误把 `storagePath` 指到 `settings.json`）被整体改名 → 界面清空 → 用户新增第一条 → 只含新条目的数组覆盖原文件；若 rename 失败则原文件在下次保存时被直接覆盖。仅有一条 toast，无「恢复备份 / 打开原文件」入口。
- **现有测试固化了该行为**：`src/test/extension.test.ts:305-319` 断言「原损坏文件应已移走」——修复时需同步改测试语义。
- **修复方向**：仅解析错误进入损坏流程；备份用**复制**（`workspace.fs.copy`）而非移走；弹模态框提供「打开原文件 / 以空数据继续 / 取消」；IO 错误不视为损坏。
- **对应任务**：M1-T1.2。

### P0-02 非原子全量写 —— ✅ 已修复（M1，见 CHANGELOG [Unreleased]）

- **位置**：`jsonFileStore.ts:33-37`（`save` 直接 `writeFile`）。
- **问题**：无临时文件、无 rename、无 fsync；进程崩溃 / 断电 / 磁盘满 / 双实例并发写可产生截断或交叉写入的文件。
- **影响**：与 P0-01 形成「写坏 → 判损坏 → 清空覆盖」的数据丢失链路。
- **修复方向**：同目录写临时文件 → 读回校验 → `workspace.fs.rename` 原子替换；`IItemStore` 契约明确「save 原子或失败不改变原文件」。
- **对应任务**：M1-T1.2。

### P0-03 `storagePath` 无路径校验，可被工作区设置覆盖并逃逸工作区 —— ✅ 已修复（M1，见 CHANGELOG [Unreleased]）

- **位置**：`package.json:430-434`（`crudStarter.storagePath` 无 `scope` 声明）、`src/extension.ts:135`（`Uri.joinPath(root, path)` 原样拼接）、`src/features/init/initSteps.ts:62-63`（初始化同样拼接）、`jsonFileStore.ts:41-42`（对解析失败的目标执行任意路径 rename）。
- **问题**：`..` 可逃逸工作区；打开恶意仓库时其 `.vscode/settings.json` 可覆盖该配置，激活后 `load()` 即对任意路径执行 rename / 覆盖写；`extension.ts:150-152` 还把配置值当 glob 传给 `RelativePattern`。
- **影响**：任意文件移走 / 覆盖（安全）+ 数据写错位置（可靠性）。
- **修复方向**：`resolveStorageUri()` 白名单（相对路径、无 `..`、无 glob 字符、`.json` 后缀、规范化后必须位于工作区内）；配置 `scope` 收紧为 `machine` 或 `application`；信任检查通过前不执行破坏性 IO。
- **对应任务**：M1-T1.1。

### P0-04 「加字段只改模型 + Schema」承诺失实：字段在 4 条路径被白名单丢弃 —— ✅ 已修复（M1，见 CHANGELOG [Unreleased]）

- **位置**：
  - `src/providers/itemFormPanel.ts:152-160`：`toItemDraft` 只映射 5 个固定字段；
  - `src/services/itemService.ts:129-142`：`validate` 只返回 5 个固定字段；
  - `itemService.ts:107-119`：`duplicate` 只复制 5 个字段；
  - `src/commands/index.ts:196-202`（追加选区）、`:268-274`（批量改优先级）、`:357-363`（更多操作改优先级）：用**树节点旧快照重建 5 字段 draft**。
- **问题**：按 README / 操作指导加 `owner` 字段后，表单能显示、能填写，但保存时被剥掉；克隆 / 改优先级 / 追加还会把已有扩展字段**清空**。
- **影响**：模板最核心卖点（低成本扩展）失实，属静默数据丢失。
- **修复方向**：领域 Schema 单一来源驱动 `coerceDraft` / `validateDraft` / `clone` / `mergePatch`；命令改为「按 id 取最新数据 + 局部覆盖」。
- **对应任务**：M5-T5.1 / T5.2（先行回归测试在 M1-T1.7）。

### P0-05 分支编译执行工作区脚本，无信任边界 / 互斥 / 取消 —— ✅ 已修复（M1，见 CHANGELOG [Unreleased]）

- **位置**：`src/features/build/buildService.ts:94-190`（`build()` 无 running 锁；`withProgress` 只包 `npm run package` 且 `cancellable: false`；`git checkout` + 工作区 `npm run package` + `npx --no-install vsce`）；`package.json` 无 `capabilities.untrustedWorkspaces`。
- **问题**：单击分支节点即在当前仓库执行任意 `package` 脚本与本地 `node_modules` 二进制，并触发 git hooks；不受信任工作区无任何拦截；两个分支可并发构建互相破坏 `dist/`；最长 300s×2 无取消。
- **影响**：不受信任仓库中的任意代码执行（安全）；工作区状态被意外改变且不回滚。
- **修复方向**：`workspace.isTrusted` 守卫 + manifest 声明 limited；互斥 + AbortController + 全流程进度；`spawn` 参数数组 + `git check-ref-format`；切换前确认、失败恢复指引。
- **对应任务**：M5-T5.4 ✅ 已修复 ✅ 已修复 ✅ 已修复 ✅ 已修复。

## 7. 测试与门禁现状评估

- **用例分布**：26 个用例集中在 `src/test/extension.test.ts` 单文件；技术上全部为宿主集成测试（需下载 VSCode，入口 `src/test/runTest.ts:9-13` 未固定版本）。
- **零覆盖区域**：`commands/index.ts`（621 行 29 命令）、`extension.ts` 激活装配、Webview 客户端逻辑（内联 JS）、`BuildService.build()`、watcher 生命周期、协议 / 校验纯函数。
- **断言质量问题**：表单用例仅断言 HTML 子串（`:387-404`）；分支断言依赖 `main`（`:261-268`）；事件计数断言与实现耦合（`:146`）；环境断言「标签存在」恒真（`:177-178`）。
- **门禁**：`scripts/gate.js` 五步（类型 → 生产构建 → 测试编译 → 静态检查 → 集成测试），最终汇总退出码正确，但非 fail-fast、硬编码模板身份、正则提取脆弱、`Module._load` stub 与 `out/` 布局强耦合。
- **结论**：现有体系验证「演示仓库自身」，不验证「模板被改名 / 被扩展后的正确性」；缺一层**快速、无宿主、高覆盖**的单元测试（本轮新增需求 NFR-07 的核心缺口）。

## 9. 根因归纳

1. **持久化契约过窄**：`IItemStore` 只有全量 `load/save`，无版本 / 原子性 / 冲突语义，可靠性问题必然在实现层反复出现；
2. **Schema 停留在渲染层**：领域校验、草稿映射、克隆各自为政 → 白名单复制 → 扩展承诺失实（P0-04）；
3. **生命周期静态绑定**：激活时一次性创建 store / watcher / 面板，环境变化后静默错位（P1-06/17）；
4. **命令基于旧快照 + 粗粒度事件**：丢失更新、N 次写盘、批量无事务（P1-05、C3）；
5. **任务 / 构建 / 初始化无生命周期契约**：无超时、取消、互斥 → 挂死与并发破坏（P1-10/11/12、P0-05）；
6. **门禁与测试面向演示仓库**：硬编码身份、断言 main 分支、无单测层 → 「改名即红」「无快速反馈」（P1-13/14/15）。
