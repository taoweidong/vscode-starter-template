## 4. 非功能需求（NFR-01 ~ NFR-13）

### NFR-01 数据可靠性（M）

- 数据文件任何情况下**不发生静默丢失**：损坏 → 备份（复制而非移走）+ 用户选择（打开原文件 / 以空数据继续 / 取消），备份失败必须显式报错；
- 写入**原子**：临时文件 + 校验 + rename；崩溃 / 断电 / 磁盘满不产生截断文件；
- 保存失败时内存缓存回滚，重试不产生重复 / 幻影数据；
- 数据格式带 `schemaVersion`，支持旧格式自动迁移；条目运行时校验 + 默认值补齐 + 坏条目隔离。

### NFR-02 并发与多窗口一致性（M）

- 首次并发加载只读一次（loadPromise）；所有写操作经串行队列；
- reload 带 generation 计数，过期结果丢弃；
- 外部修改检测（mtime / 内容哈希）+ 冲突提示，后写不静默覆盖先写；
- 工作区切换 / `storagePath` 变更时重建 store 与 watcher，数据不写错位置。

### NFR-03 安全边界（M）

- `storagePath` 白名单：拒绝绝对路径、`..`、NUL、glob 字符，强制 `.json` 后缀，目标必须位于工作区内；配置作用域收紧；
- Workspace Trust：不受信任工作区禁用分支编译等执行工作区脚本的能力；manifest 声明 `capabilities.untrustedWorkspaces`；
- shell 执行一律参数数组（`spawn`），外部输入先 `git check-ref-format` / 白名单；
- Webview：严格 CSP（见 03 §6.4）、禁止 `v-html`、消息运行时校验、`localResourceRoots` 最小化。

### NFR-04 扩展契约（M）

| 扩展场景 | 承诺步数                                                                | 验证                                |
| -------- | ----------------------------------------------------------------------- | ----------------------------------- |
| 加字段   | 模型 + 领域 Schema 两处，表单 / 校验 / 克隆 / 追加 / 复制全链路自动生效 | 回归测试：新增 `owner` 字段往返不丢 |
| 换数据源 | 实现 `IItemStore`（含可选批量 / 版本能力），业务与页面零改动            | 内存 Store 集成测试                 |
| 加命令   | constants → package.json → commands 三处                                | 门禁结构化校验（含注册检查）        |
| 加任务   | 实现 `StartupTask` + 注册表一项                                         | 框架单测（超时 / 取消 / 异常隔离）  |
| 加页面   | 页面注册表一项 + 页面目录                                               | 画廊与组件测试                      |

### NFR-05 性能与规模（S）

- 500 条目下：树刷新 < 200ms；2000 条目可用（分组一次遍历，O(N)）；
- 批量操作（50 条）一次读盘一次写盘一次事件，带进度与取消；
- 激活不阻塞（启动任务后台执行）；环境探测总时长有上限（并行 / 缓存）。

### NFR-06 UI 与可访问性（M）

- 颜色只用 `--vscode-*`（经语义令牌）；单一字体字阶；间距 4/8/12/16/24；控件 26px / 圆角 2px；
- 主按钮在右；动效 0.1s 并尊重 `prefers-reduced-motion`；
- 键盘全可达（Esc / Ctrl+Enter / Tab 顺序 / 焦点可见）；`aria-invalid` / `aria-describedby`；
- 高对比度主题可用；深 / 浅色自动适配。

### NFR-07 测试体系与质量协议（M ★ 本轮强化）

**三层测试**：

| 层      | 工具                                                | 内容                                                               | 时长要求             |
| ------- | --------------------------------------------------- | ------------------------------------------------------------------ | -------------------- |
| L1 单元 | Vitest（无 VSCode 宿主，`vscode` 模块以 stub 注入） | services / stores / 领域 Schema / 命令纯函数 / 协议守卫 / 路径解析 | < 30s，不下载 VSCode |
| L2 组件 | Vitest + Vue Test Utils + jsdom                     | Vue 组件渲染 / 校验 / 交互 / 状态矩阵                              | 并入 L1              |
| L3 集成 | Mocha + @vscode/test-electron                       | 激活、树视图、命令装配、Webview 面板 HTML/CSP                      | 按需（门禁 / CI）    |

**覆盖率**：整体 lines / branches ≥ 70%（下限）；`src/services`、`src/models`、领域 Schema、`src/webview/protocol.ts` ≥ 85%（下限）；阈值进入门禁，只升不降。

> 07 R-E-15：**「≥85%」是文档下限，不是当前阈值**。`src/domain` 因 `coerceBooleanField` 为预留路径
> （生产字段表暂无 boolean 字段）实测约 82L/74B，当前配置阈值取 81/73，接入首个 boolean 字段后升回 85。
> 「文档下限 vs 配置阈值 vs 实测」对照表维护在 `docs/需求与优化方案/03 §6.2`。

**质量协议（已写入 `agent.md`）**：

1. 每一轮对话结束前、每一次 `git commit` 前，必须执行并通过单元测试（过渡期以 `npm run gate` 代替；M2 落地 `npm run test:unit` 后：日常轮次跑 `test:unit`，提交前跑完整 `gate`）；
2. 新增代码必须**优先补充单元测试**：新模块 / 新命令 / 新服务方法 / 新组件随代码提交对应单测；修复 bug 先写复现测试再修复；
3. 单元测试不得跳过、注释或伪造通过；不可测的代码先重构可测性。

### NFR-08 工程化与持续集成（M）

- 门禁 fail-fast；步骤 = 类型检查（tsc + vue-tsc）→ 双构建 → 静态结构化校验 → 单元测试 → 集成测试 → `vsce ls` 打包校验；
- ESLint（flat config，TS）+ Prettier 检查进入门禁；
- GitHub Actions：Windows + Ubuntu（xvfb），`npm ci`，缓存 `.vscode-test`，跑 `test:unit` + `gate`；
- 无 JS 源文件检查（源码树禁止 `.js`，构建产物除外）。

### NFR-09 文档与发布一致性（M）

- README / agent.md / 操作指导与实现零漂移（已知偏差清单见 02 §8，修复任务见 M6）；
- 发布元数据齐备：LICENSE、128×128 PNG 图标、publisher、categories、repository；
- Marketplace 上的 README 链接不指向未打包进 vsix 的相对路径（docs 链接改绝对 URL 或调整打包策略）。

### NFR-10 技术栈统一（M · 本轮确立）

- 源码、构建脚本、门禁脚本、测试全部 TypeScript；`.vue` 使用 `<script setup lang="ts">`；
- 允许的例外：`dist/`、`out/` 构建产物、JSON / YAML / SVG / CSS；
- Vue 只进入 Webview 产物，扩展宿主运行时依赖保持为零。

### NFR-11 VSCode 视觉一致性（M · 本轮确立）

- 组件只消费语义令牌（见 04 文档令牌表）；禁止硬编码颜色（`#` / `rgb(` / `hsl(`）、禁止通用 UI 框架；
- 视觉验收基线：组件画廊 × {默认 / hover / focus / disabled / invalid / loading} × {Dark+ / Light+ / 高对比度}；
- 样式规则由门禁自动检查（正则 + 导入白名单）。

### NFR-12 前端可测试性与视觉验收（M）

- 组件有对应 Vitest 用例（渲染 / 交互 / 状态）；
- 画廊页可在真实 Webview 中人工巡检；后续可接 Playwright 截图回归（可选）；
- 宿主 HTML 外壳（CSP / 资源引用 / data-page）有纯函数级测试。

### NFR-13 构建与包体预算（S）

- Webview 单页 JS+CSS ≤ 200KB（minified，Vue runtime 含内）；VSIX ≤ 300KB（不含图标资源时）；
- 构建产物带隐藏 sourcemap（不进 vsix）；
- 构建可复现：锁版本、锁 lockfile、CI 与本地同命令。

## 6. 范围外与假设

**范围外**：多人协作 / 云同步、拼音搜索、国际化（i18n）、把 6 个原生 TreeView 改写为 Webview、发布到 Marketplace 的自动化流水线（仅做 `vsce package`，`publish` 保留手工）。

**假设**：

- 「页面」指 Webview 页面；原生 TreeView 由 VSCode Extension API 渲染，不迁移 Vue；
- 开发环境 Node ≥ 20（Vite/Vitest 现行版本要求），扩展运行时仍以 `engines.vscode ^1.85` 为准；
- 「一键打包」解释为 `npm run package:vsix` 一条命令产出离线 .vsix（含工具链内置，无需全局安装）。

## 7. 术语表

| 术语            | 含义                                                                           |
| --------------- | ------------------------------------------------------------------------------ |
| 宿主（Host）    | 扩展进程侧代码（Node 环境，可 import `vscode`）                                |
| Webview         | VSCode 内嵌网页（浏览器环境，经 postMessage 与宿主通信）                       |
| 领域 Schema     | 纯 TS 的字段定义，同时驱动表单渲染与服务端校验（区别于仅 UI 的 `FORM_SCHEMA`） |
| 语义令牌        | `--ui-*` CSS 变量，映射到 `--vscode-*` 主题变量，组件只消费前者                |
| 画廊（Gallery） | 集中展示组件 × 状态 × 主题的开发者页面，视觉验收基准                           |
| 门禁（Gate）    | `npm run gate` 一键式质量检查流水线                                            |
