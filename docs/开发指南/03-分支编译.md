# 03 · 分支编译

> 「分支编译」视图：选一个分支 → 安全校验 → 切换 → `npm run package` 编译出包 →
> 可选 vsce 打 .vsix。异步长任务的完整教学样板：`withProgress` 可取消、模态确认、
> 进程树杀、互斥重入保护。

## 核心机制（执行流水线）

```
build(branch?)
 1. 受信任工作区校验（isTrusted === false 拒绝执行）
 2. 未打开工作区 → error 结果（不抛错）
 3. git 可用性 + 分支清单（getGitInfo）
 4. git check-ref-format 校验目标分支名（防注入：spawn 参数数组，无 shell 拼接）
 5. 脏检查：git status --porcelain → filterDirtyLines 按「忽略前缀」过滤
    └ 精确路径相等 或 `/` 结尾目录前缀（无 glob）；重命名行双边判定；带引号路径 unquote
 6. 仍有脏文件 → 模态确认（列出示例文件）→ 取消则中止
 7. withProgress 可取消 → git checkout → npm run package → vsce --version 探测（有则打 vsix）
    └ 取消：TaskSignal → kill 子进程树（BuildCancelledError）
 8. 结果分级：ok / warn（有告警）/ error；互斥：isRunning 期间二次调用直接拒绝
```

## 扩展实操

### A. 新增工作区数据文件的忽略（**最高频改动，必读**）

凡是插件会写入工作区的数据文件，**三处字面量同步**（匹配无 glob）：

1. `src/extension/features/build/buildService.ts` → `DEFAULT_DIRTY_IGNORES` 数组加一行；
2. `.gitignore` 加对应条目；
3. 数据落点常量（如 `constants.ts` 的 `draftsFileName`）保持同值。

漏第 1 处的后果：用户用过一次该功能 → 数据文件成为未提交修改 → **分支编译永远被
脏检查自阻断**（v0.7.0 串口踩过的真实事故）。若忽略路径需动态求值，走构造选项
`getDirtyIgnorePrefixes` 注入（B1 保留的扩展点），不要在组装期写死快照。

### B. 改构建命令 / 产物形态

构建命令集中在 `buildService.ts` 的流水线步骤（`npm run package` 与 vsce 探测），
改命令即改 `CommandSpec`（spawn 参数数组形态）。测试时经构造选项
`{ runCommand: async (spec) => '...' }` 注入假执行器，不用真跑。

## 常见坑

- `filterDirtyLines` 的匹配是**前缀语义**（精确相等或目录前缀），不是 glob——写
  `'.vscode/*.json'` 无效，必须逐个写字面量；
- 子进程一律 `spawn` 参数数组（`CommandSpec`），**禁止**把用户输入拼进 shell 字符串
  （agent.md 硬性规约 #6）；
- vsce 未安装（探测失败）不是错误——编译仍成功，只是不出 .vsix（warn 提示）。
