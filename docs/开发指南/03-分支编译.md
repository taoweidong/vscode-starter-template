# 03 · 分支编译（构建控制台）

> v2.0 改造：分支编译 = **Webview 弹框表单 → HTTP 接口提交 → 轮询任务列表展示**。
> 原本地 git 流水线（BuildService / buildView 树视图）已退役；HTTP 接口**默认打桩模拟**，
> 配置 `extStarter.buildApiBaseUrl` 后切换真实接口——页面与协议层零改动。

## 核心机制

```
命令 buildBranch → BuildConsolePanel.createOrShow → WebviewController（pageId=buildConsole）
  页面 ready → init（schema = BUILD_FIELD_DEFS 派生）
  页面 submit（通用提交生命周期）→ deps.onSubmit → api.submit
      ├ baseUrl 空 → StubBuildApiClient：内存任务表 + 定时器模拟
      │   queued(1.5s) → running(进度 tick 600ms/step14) → success|failed
      │   确定性失败规则：分支名含 fail（演示失败路径，无随机数）
      └ baseUrl 非空 → HttpBuildApiClient：POST /builds（Node 20 全局 fetch）
      resolve → 控制器回 submitAck（解锁表单）；抛错 → error（field 定位控件）
  页面每 3s buildListRequest → api.list() → buildList{tasks} 全量刷新
```

- **服务端契约**（真实接口）：`POST /builds`（`BuildSubmitPayload` → `BuildTask`）、
  `GET /builds`（`BuildTask[]`），字段定义见 `buildApiClient.ts`；
- **任务状态**：`queued / running / success / failed`，进度 0-100，时间均为 ISO 字符串；
- **表单**：SchemaForm 由字段表驱动（text / select / textarea），分支名必填校验失败经
  `error.field = 'branch'` 回传定位控件。

## 扩展实操

### A. 对接真实 HTTP 接口（预留路径，零改页面）

1. 配置 `extStarter.buildApiBaseUrl`（如 `http://127.0.0.1:3000`）；
2. 服务端实现两个端点（契约见上）；字段或路径不一致时**只改 `HttpBuildApiClient`**。

### B. 表单加一个字段

`buildSchema.ts` 的 `BUILD_FIELD_DEFS` 加一行（类型 text / select / textarea），
提交侧在 `buildConsolePanel.ts` 的 `onSubmit` 里补对应取值与校验。表单渲染、
默认值、错误定位全部自动跟随。

### C. 加一个列表操作能力（如取消构建）

1. `protocol.ts` 加消息分支 + 守卫 case（如 `buildCancel { id }`）；
2. `buildApiClient.ts` 接口加方法（Stub 同步实现，Http 加 DELETE /builds/:id）；
3. 页面加操作按钮 → `post({ type: 'buildCancel', id })`。

### D. 改打桩演示行为

`StubBuildApiClient` 顶部常量：提交延迟 / 排队时长 / 进度步长 / 任务上限；
失败规则 `willFail()`（当前按分支名，可换成随机或按 notes）。

## 历史说明（v1.x → v2.0）

v1.x 的分支编译是本地流水线：buildView 树视图选分支 → 脏检查 → `git checkout` →
`npm run package` → vsce 打 vsix（`BuildService`，559 行）。该实现随 v2.0 弹框改造
整体退役；「异步长任务 + 可取消 + 互斥」的教学价值由启动任务框架（开发指南 01）
与打桩任务生命周期承载，脏检查忽略清单的教训沉淀为 `.gitignore` 约定
（见开发指南 README 铁律 3）。
