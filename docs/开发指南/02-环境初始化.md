# 02 · 环境初始化

> 「环境初始化」视图：步骤清单式编排——检查工作区 → 创建构建产物目录 → 写入环境快照。
> 单步可执行、可重跑，整体「全部初始化」一键串行。

## 核心机制

- **步骤定义**：`{ id, title, description, timeoutMs?, run(ctx) }`，`run` 返回成功信息字符串、
  失败直接抛错（由 InitService 记为 failed）；
- **状态机**：`idle → running → done|failed`，单步失败**不阻断**后续步骤；
  `runAll` 执行期间 `runStep` 被忽略（互斥，防并发写同一文件），且有可见提示（不只是日志）；
- **超时**：默认 120s（`INIT_STEP_TIMEOUT_MS`），挂死步骤被裁决为 failed；
- **快照复用**：`envSnapshot` 步骤优先复用启动任务已缓存的环境检测结果
  （`createInitSteps({ getEnvironmentSnapshot })` 注入，由 extension.ts 接通 TaskRunner），
  避免最坏约 48s 的重复全量探测；
- **工件目录**：`.ext-starter/`（gitignore + `DEFAULT_DIRTY_IGNORES` 均已忽略），
  环境快照写 `.ext-starter/environment.json`；单步重跑 envSnapshot 时会兜底重建目录。

## 扩展实操：新增一个步骤

```ts
// initSteps.ts 的 createInitSteps() 数组加一项（顺序 = 执行顺序）
{
  id: 'my-step',
  title: '我的步骤',
  description: '确认 xxx 就绪',
  async run(ctx) {
    if (!ctx.workspaceRoot) {
      throw new Error('未打开工作区。') // 依赖工作区的步骤统一先判空
    }
    // …动作…
    return '完成信息（展示在树视图与输出通道）'
  },
}
```

无需改动 InitService / 树视图 / 命令——注册表驱动。需要注入依赖时扩展
`CreateInitStepsOptions` 并在 `extension.ts` 组装处传入（快照复用即此模式）。

## 常见坑

- 步骤间**不要隐式依赖执行副作用**：envSnapshot 已做目录兜底，但新步骤若依赖前面步骤的
  产物，请在自身 `run` 里自行确保（幂等优先）；
- 抛错文案会原样展示给用户（树视图 message 列），直接写人话，别抛堆栈；
- `.ext-starter/` 改名时三处字面量联动：`initSteps.ts`、`buildService.ts` 的
  `DEFAULT_DIRTY_IGNORES`、`.gitignore`。
