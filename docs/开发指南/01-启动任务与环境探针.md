# 01 · 启动任务与环境探针

> VSCode 窗口加载完成即自动执行（`onStartupFinished`，无需打开文件夹或点击插件）：
> 先跑「初始化脚本」（内置演示 Hello World），再跑「环境检测」（探针注册表），
> 全过程逐行打印到输出通道。「环境信息」视图实时展示分组结果。

## 核心机制

```
窗口加载完成（onStartupFinished）
  → activate()：runStartupTasks=true（默认）时 void taskRunner.runAll()   // 不 await，不阻塞激活
  → TaskRunner.runAll()：按 TASKS 数组顺序逐个执行
      每任务：超时裁决（Promise.race，默认 60s）/ 异常降级为 error 结果 / 取消信号
      每任务完成：formatTaskResult 逐行写输出通道 + onDidChangeItems 事件 → 树视图刷新
```

- **控制台**：输出通道名 `Extension Starter`，命令面板「Extension Starter: 打开环境信息输出」查看；
- **树视图**：每个任务一个分组（`TaskResult`），其下是条目（`TaskItem`）——按状态自动选
  codicon（`STATUS_ICONS`），新增任务**零改动视图**自动出现新分组；
- **单探针重检**：探针条目的 `TreeItem.command` 绑定 `refreshEnvironment` + label 参数，
  经 `recheckProbeByLabel` 只跑目标探针、`TaskRunner.updateItem` 就地替换条目并重算任务状态。

## 扩展实操

### A. 新增一种环境探针（一条数据）

```ts
// src/extension/tasks/probes.ts —— ENVIRONMENT_PROBES 数组加一项
{
  id: 'go',
  label: 'Go',                       // 展示名 = 树视图条目 label = 单击重检路由键
  commands: ['go version'],          // 候选命令按序回退，首个有输出者胜出
  parse: (raw) => raw.replace(/^go\s*/i, ''),  // 从输出提取版本号，可省略
  missingHint: '未检测到：安装 Go 或加入 PATH', // 缺失提示，可省略
}
```

完成。检测条目、缺失提示、单击单独重检全部自动跟随。**命令输出语义**：退出码非 0
一律视为失败（即使 stdout 有内容）；退出码 0 且 stdout 为空时接受 stderr 首行
（兼容旧版 Python / Java 的 `--version` 走 stderr 的行为）。

### B. 新增一个启动脚本（动作类任务）

```ts
// src/extension/tasks/myScript.ts —— 抄 helloTask.ts
import type { StartupTask, TaskContext, TaskResult } from './types'

export const myTask: StartupTask = {
  id: 'my-script',
  title: '我的脚本',
  timeoutMs: 10000, // 缺省 60s
  async run(ctx: TaskContext): Promise<TaskResult> {
    ctx.output.appendLine('[我的脚本] 执行中…') // 实时打印到控制台
    return {
      taskId: 'my-script',
      taskTitle: '我的脚本',
      status: 'ok',
      durationMs: Date.now() - startedAt,
      finishedAt: new Date().toISOString(),
      items: [{ label: '条目名', description: '值', status: 'ok' }],
    }
  },
}
// taskRegistry.ts：TASKS = [helloTask, myTask, environmentTask]
```

调度、超时、异常降级、控制台打印、视图分组全部自动生效。`items[].status` 取
`'ok' | 'missing'`（条目级）与任务级 `'ok' | 'warn' | 'error'`——有非 ok 条目时任务自动降为 warn。

## 常见坑

- `runAll()` 在 activate 里**不 await**——任务里不要假设激活已完成；探测走子进程，
  单任务超时默认 60s（`DEFAULT_TASK_TIMEOUT_MS`）；
- 探针 `parse` 收到的是**输出首行**（`execCapture` 已 trim）；多行输出先自行取行；
- 自动执行受 `extStarter.runStartupTasks` 控制（manifest 默认 `true`），
  改默认值时记得同步 `package.nls*.json` 描述与 `index.ts` 里的 `get(..., true)` 兜底。
