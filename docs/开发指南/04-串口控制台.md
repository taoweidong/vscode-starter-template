# 04 · 串口控制台

> 唯一的「真实业务」示例：服务器录入（密码进 SecretStorage）→ 连接下发命令 →
> 实时输出 → 历史命令 MRU 去重。覆盖存储双实现、协议守卫、链路状态机、
> 面板生命周期——二次开发任何「带数据 + 带页面」的功能都照它的样子长。

## 核心机制

- **协议**：串口相关 15 个消息分支（`HostMessage` 5 + `WebviewMessage` 10），全部经
  `protocol.ts` 运行时守卫逐字段窄化——未知消息只记日志不抛错；
- **存储**：有工作区 → `.vscode/serial-servers.json`（原子写 + 损坏自动备份 .bak +
  空数据恢复）；无工作区 → globalState Memento 兜底。同键双实现对页面透明；
- **密码**：只存 `SecretStorage`（键 `extStarter.serialServer.<id>.password`），
  数据文件与日志零明文；v0.x 旧键在**首次自动登录时惰性搬迁**（读旧 → 写新 → 删旧）；
- **链路**：单连接状态机（connecting/connected/disconnected/error），输出 40ms 批处理
  防消息洪泛，断开/换服务器经 generation 代际守卫防乱序；面板关闭自动断开；
- **自动登录**：连接后 800ms 发用户名、再 500ms 发密码（时序常量可注入），凭据不进历史。

## 扩展实操

### A. 给服务器表单加一个字段（一处定义）

```ts
// serverSchema.ts —— SERVER_FIELD_DEFS 加一行
{ key: 'location', type: 'text', label: '位置', placeholder: '选填' }
```

表单渲染、校验、回填、存储、协议透传（`SerialServerWire` 带 `[extra: string]: unknown`）
全部自动跟随。需要强类型提示时再同步 `models.ts` 的 `SerialServer`。

### B. 新增一条协议消息（三处）

1. `src/webview/protocol.ts`：`HostMessage`（宿主→页面）或 `WebviewMessage`（页面→宿主）
   联合类型加分支 + 对应守卫 `case`（逐字段窄化，参考现有串口分支）；
2. 宿主侧：`serialConsolePanel.ts` 的消息分发里处理（页面来的）或 `post`（下发给页面）；
3. 页面侧：`apps/serialConsole/App.vue` 的 message 监听里处理。

协议分支删除后必须同步删守卫 case 与两侧处理（`protocol.ts` 当前 22 分支 =
通用 7 + 串口 15）。

## 常见坑

- `serialport` 是唯一生产依赖：esbuild `external` + `.vscodeignore` 否定项随包分发
  prebuild，改动打包配置时先跑 `npm run gate` 第 ⑨ 步（黑白名单会拦）；
- 新命令必须挂 `guard()`（`serialConsoleEnabled` 开关关闭时给可操作提示）；
- 页面内一切下发都要走 `postMessage` + 守卫，**禁止**在页面直接 import 宿主代码
  （边界规则：`src/webview/**` 不 import vscode）。
