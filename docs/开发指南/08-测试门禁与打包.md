> 改完代码到「可交付」的全部机械步骤都在这里。

## 测试分层

| 层   | 命令                | 速度            | 覆盖什么                                                |
| ---- | ------------------- | --------------- | ------------------------------------------------------- |
| 单元 | `npm run test:unit` | ~20s            | 全部逻辑（vitest + jsdom + vscode 桩，含 Vue 组件）     |
| 集成 | `npm test`          | 首次下载 VSCode | 真实 vscode API 下的服务 / 构建流水线                   |
| e2e  | `npm run test:e2e`  | ~10s            | 构建产物在真实浏览器中的交互 + **codicon 字体加载断言** |

**vscode 桩**（`src/test/unit/stubs/vscode.ts`）：EventEmitter / 录制器（`__stubs.recorded`）/
config 双层存储（全局 + 工作区，`__setConfig`）/ workspace.fs（真实 Node fs）/ 对话框队列
（`__stubs.dialogQueue`）。**只许增量扩展、不得删除已有导出**。

写一个 spec 的惯用法：

```ts
__resetStubs() // 每用例先清副作用
__setConfig('extStarter', 'runStartupTasks', false) // 配置
__stubs.dialogQueue.push('删除') // 排队模态应答
const line = __stubs.outputLines.at(-1) // 断言输出通道内容
```

## 门禁（提交前必跑）

```bash
npm run gate -- --fast   # 日常：9 步中跳过第⑧步宿主集成
npm run gate             # 收尾 / 推送前：完整 9 步
```

①lint/格式 → ②类型（tsc strict + vue-tsc）→ ③宿主构建 → ④Webview 构建 → ⑤测试编译 →
⑥静态一致性（清单闭合 / 样式门禁 / 产物 CSP 与绝对引用红线）→ ⑦单测（覆盖率阈值：
整体 92L/93F/92S/87B，`protocol.ts` 100%）→ ⑧宿主集成 → ⑨vsce 黑白名单 + bundle 预算
（宿主 ≤150KB、单 chunk ≤100KB、vsix ≤20MB）。

## 打包与归档

```bash
npm run package:vsix            # 完整构建 + vsce 打包 → release/<name>-<version>.vsix
npm run package:vsix -- --clean # 先清空 release/ 重新归档
```

- 跨平台纯 Node 实现（`scripts/package-vsix.ts`）；Windows 双击根目录 `package.bat`
  （CLI 用法 `package.bat [--clean]`，`SKIP_PAUSE=1` 供脚本调用）；
- 产物统一进 `release/`（gitignore + vscodeignore 双排除，根目录保持整洁）；
- 离线验证：扩展面板 `…` → 从 VSIX 安装。

## 版本号规约（强制，详见 agent.md）

- **每个含代码变更的提交，同一提交内升 `package.json` 的 `version` 并记 `CHANGELOG.md`**；
- major = 破坏性（ID/存储键/清单结构/删公开能力）；minor = 向后兼容新功能；patch = 修复/重构/工具链；
- 纯文档 / CI 提交豁免；拿不准从严。
