> 命令 / 视图 / 配置 / 存储 ID 的单一来源与清单闭合校验；manifest 文案的

## 核心机制

- **三方闭合**：`constants.ts` 的 `COMMAND.xxx` ↔ `package.json` contributes 命令 ↔
  `src/extension/commands/**` 的 `register(COMMAND.xxx` ——门禁静态扫描，缺一即红；
- **前缀动态化**：门禁从编译产物 `out/extension/constants.js` 读 `CONFIG.section`
  生成匹配正则——**改 ID 前缀不需要改门禁**（v1.0.0 改名迁移的教训沉淀）；
- **菜单 when**：树条目菜单用 `viewItem == <contextValue>`（`TreeItem.contextValue`），
  编辑器选区用 `editorTextFocus && editorHasSelection`，资源管理器多选用
  `listMultiSelection`；
- **i18n 机制**：`package.json` 写 `"title": "%command.xxx.title%"`，VSCode 按
  `package.nls.json`（默认）与 `package.nls.<locale>.json`（如 `zh-cn`）替换。
  注意这只覆盖 **manifest 静态文案**；运行时文案（如 `showInformationMessage`）
  用 `vscode.l10n` 是另一套机制，本项目未引入。

## 扩展实操：新增一个命令（完整五步）

1. `constants.ts` → `COMMAND` 加 ID（如 `myFeature: 'extStarter.myFeature'`）；
2. `package.json` → `contributes.commands` 加声明（title/category 用 `%key%` 占位符）；
3. `package.nls.json` + `package.nls.zh-cn.json` 各加文案（键名不带前缀，改名不用同步）；
4. `src/extension/commands/` 对应场景分组写实现：`register(COMMAND.myFeature, ...)`；
5. 需要菜单 / 快捷键时配置 `contributes.menus` / `keybindings`（keybindings 可选，
   存在即被门禁校验引用闭合）。

新增**视图**同理：`VIEW` 加 `xxxViewId` → `viewsContainers` / `views` 声明 →
`extension.ts` 组装 `createTreeView` → 菜单 when 用新视图 ID。

## 常见坑

- 漏 nls 键 → 界面显示 `%command.xxx.title%` 原文；两份语言文件**键集必须一致**；
- `keybindings` 从 package.json 整体删除是合法的（门禁按可选处理），但**保留时**每条
  引用的命令必须在清单声明；
- 子菜单（`submenus`）当前为 0——要加时记得 `submenus` 声明 + `menus` 挂载 + 子菜单节
  三处（门禁会校验引用闭合）；
- 配置项 `configuration.properties` 的键以 `extStarter.` 开头，与 `CONFIG.section` 保持
  同前缀（改名迁移脚本与 legacyMigration 依赖这一约定）。
